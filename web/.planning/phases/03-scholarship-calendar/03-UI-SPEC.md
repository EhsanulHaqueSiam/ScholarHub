## Color

Uses existing CSS custom properties. No new colors introduced. Phase 03 maps existing urgency tokens (already defined in `index.css`) to calendar elements:

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / oklch(96% 0.008 75) | Page background, calendar grid background |
| Secondary (30%) | `--secondary-background` / oklch(99.5% 0 0) | Calendar day cells, day detail panel, insight banner card |
| Accent (10%) | `--main` / oklch(55% 0.24 264) | "Today" indicator ring on current date, active month navigation button, selected day highlight border |
| Destructive | `--destructive` / oklch(52% 0.24 27) | Not used in this phase (no destructive actions) |
| Success | `--success` / oklch(60% 0.19 150) | Not directly used (available for future "submitted" overlay) |

### Deadline Urgency Colors (existing tokens from index.css)

Deadline chips on calendar days use the existing urgency badge variants. The urgency thresholds:

| Urgency | Token | Badge Variant | Threshold |
|---------|-------|---------------|-----------|
| Critical | `--urgency-critical` / oklch(58% 0.24 27) | `urgencyCritical` | <= 7 days from today |
| Warning | `--urgency-warning` / oklch(78% 0.15 80) | `urgencyWarning` | 8-30 days from today |
| Open | `--urgency-open` / oklch(60% 0.19 150) | `urgencyOpen` | > 30 days from today |
| Closed | `--urgency-closed` / oklch(65% 0.01 0) | `urgencyClosed` | Deadline has passed |

### Source Overlay Colors (tracked vs shortlisted)

To distinguish where a calendar event came from, deadline chips show a left-edge indicator:

| Source | Left Border Color | Rationale |
|--------|-------------------|-----------|
| Tracked scholarship | `--main` / oklch(55% 0.24 264) | Matches tracker accent in Phase 02 |
| Shortlisted scholarship | `--accent` / oklch(82% 0.19 90) | Matches shortlist yellow accent |
| Both (tracked + shortlisted) | `--main` / oklch(55% 0.24 264) | Tracked takes priority (higher engagement signal) |

### "Today" Indicator

The current date cell receives a 3px `--main` border (inner ring) to visually anchor the user. No background fill change -- just the ring.

### Accent Reserved For (explicit list)

1. "Today" ring on the current date cell
2. Active/pressed state of month navigation arrows
3. Selected day cell border (when user clicks a day to see detail)
4. Peak season insight banner left border accent stripe

## Interaction Contract

### Month Navigation

| Interaction | Behavior |
|-------------|----------|
| Previous month arrow | Navigate to previous month; 150ms slide-left transition (motion-safe) |
| Next month arrow | Navigate to next month; 150ms slide-right transition (motion-safe) |
| Keyboard | Left/Right arrow keys on focused navigation to change month |
| Month/year label | Static text, not interactive |
| URL sync | Current month encoded in URL search param `?month=2026-04` for shareability and back-button support |

### Day Cell Interaction

| Interaction | Behavior |
|-------------|----------|
| Click/tap day with deadlines | Opens day detail panel below the grid (desktop) or slides up from bottom (mobile) |
| Click/tap day without deadlines | No action (cursor: default) |
| Click/tap already-selected day | Closes the day detail panel |
| Hover day with deadlines | Subtle background shift to `--secondary-background` with 2px border-border (desktop only) |
| Keyboard | Tab focuses day cells with deadlines only (skip empty days), Enter/Space opens detail panel |
| Focus indicator | 2px `--ring` outline on focused day cell |

### Deadline Chip Interaction (Desktop)

| Interaction | Behavior |
|-------------|----------|
| Click chip | Navigates to scholarship detail page (`/scholarships/[slug]`) |
| Hover chip | Chip lifts with 2px shadow increase, cursor: pointer |
| Overflow "+N more" | Clicking opens day detail panel (same as clicking the day cell) |

### Day Detail Panel

| Interaction | Behavior |
|-------------|----------|
| "View Scholarship" button | Navigates to `/scholarships/[slug]` |
| Close | Click outside panel, press Escape, or tap the selected day cell again |
| Desktop render | Inline below the calendar grid, 150ms slide-down transition (motion-safe) |
| Mobile render | Bottom sheet sliding up from viewport bottom, 200ms slide-up transition (motion-safe), 50% viewport max height, scrollable |

### Peak Season Banner

| Interaction | Behavior |
|-------------|----------|
| Render condition | Shown when the displayed month has 3 or more deadlines |
| Dismiss | Not dismissible -- informational only, re-evaluates per month |
| Content | Dynamic: "Busy month ahead -- you have [N] deadlines in [Month]" |

## State Contract

### Data Sources (read-only, no new storage)

The calendar introduces no new localStorage keys. It reads from:

1. **Static JSON** (`useStaticData()`) -- `ScholarshipSummary.application_deadline` (unix ms timestamp) for all scholarships
2. **Application Tracker** (`useApplicationTracker()`) -- `TrackerEntry.scholarshipSlug` to identify tracked scholarships
3. **Shortlist** (`useLocalStorage("scholarhub_shortlist")`) -- shortlisted scholarship slugs

### Computed Data (deadline engine)

```typescript
// lib/calendar/deadline-engine.ts (new, pure function)

interface CalendarEvent {
  scholarshipSlug: string;
  scholarshipTitle: string;
  deadlineMs: number;
  source: "tracked" | "shortlisted" | "both";
  urgency: "critical" | "warning" | "open" | "closed";
  prestigeTier: string | null;
}

interface MonthData {
  year: number;
  month: number; // 0-indexed
  events: CalendarEvent[];
  eventsByDay: Map<number, CalendarEvent[]>; // day-of-month -> events
  totalDeadlines: number;
  isPeakSeason: boolean; // 3+ deadlines in month
}

function getMonthData(
  scholarships: ScholarshipSummary[],
  trackedSlugs: Set<string>,
  shortlistedSlugs: Set<string>,
  year: number,
  month: number,
): MonthData;

function computeUrgency(deadlineMs: number, now: number): "critical" | "warning" | "open" | "closed";
```

### UI States

| State | What Renders |
|-------|-------------|
| Loading (static data fetching) | Skeleton: 7-column grid with pulsing gray cells, no chips |
| Empty (no tracked/shortlisted with deadlines) | `CalendarEmptyState` with CTA to browse scholarships |
| Populated (1+ deadlines visible in any month) | Full calendar grid with deadline chips |
| Day selected | Day cell highlighted with `--main` border, detail panel open below grid |
| No deadlines in current month | Calendar grid renders normally but all cells are empty; no insight banner shown; subtle hint text below grid: "No deadlines this month. Try navigating to another month." |
| Storage error | `StorageErrorBanner` at page top |

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Calendar grid role | `role="grid"` on the calendar container, `role="row"` on each week row, `role="gridcell"` on each day cell |

## react-big-calendar Integration

### Library Choice Rationale

**Using react-big-calendar 1.19.4** (not react-day-picker) per STACK.md recommendation. react-big-calendar provides month/agenda views out of the box -- the agenda view is valuable for mobile as a list-based fallback. react-day-picker is a date picker, not an event calendar, and does not support multi-event day rendering.

Note: ARCHITECTURE.md recommended react-day-picker, but STACK.md recommended react-big-calendar. The STACK.md recommendation is correct for this use case: the calendar needs to render multiple events per day with urgency coloring, which react-day-picker does not support without heavy custom rendering.

### CSS Override Strategy

react-big-calendar ships its own CSS (`react-big-calendar/lib/css/react-big-calendar.css`). Override to match neo-brutalism:

| Override Target | `.rbc-*` Selector | Neo-Brutalism Value |
|----------------|-------------------|---------------------|
| Border radius | `.rbc-event`, `.rbc-toolbar`, `.rbc-month-view` | `border-radius: 0px` |
| Borders | `.rbc-month-view`, `.rbc-day-bg`, `.rbc-header` | `border: 2px solid var(--border)` |
| Shadows | `.rbc-event` | `box-shadow: var(--shadow)` on hover only |
| Font family | `.rbc-toolbar`, `.rbc-header`, `.rbc-date-cell` | `font-family: var(--font-base)` / `var(--font-heading)` for headers |
| Today highlight | `.rbc-today` | `border: 3px solid var(--main)` (ring, not background fill) |
| Event colors | `.rbc-event` | Dynamic class based on urgency: `bg-urgency-critical`, `bg-urgency-warning`, `bg-urgency-open`, `bg-urgency-closed` |
| Toolbar | `.rbc-toolbar` | Custom `MonthNavigation` component replaces default toolbar entirely via `components={{ toolbar: MonthNavigation }}` |
| Background | `.rbc-off-range-bg` | `background: var(--background)` (no gray tint for out-of-range days) |
| Selected | `.rbc-selected` | `border: 2px solid var(--main)` |

### Custom Component Overrides

react-big-calendar supports `components` prop for replacing internal UI:

```typescript
<Calendar
  localizer={dateFnsLocalizer}
  events={calendarEvents}
  views={["month", "agenda"]}
  defaultView="month"
  components={{
    toolbar: MonthNavigation,           // custom month nav with neo-brutalism
    event: DeadlineChip,                // custom event renderer with urgency colors
    month: { dateHeader: DayHeader },   // custom day number with today ring
  }}
  onSelectEvent={handleEventClick}      // navigate to scholarship detail
  onNavigate={handleMonthChange}        // sync month to URL param
/>
```

### date-fns Localizer

```typescript
import { dateFnsLocalizer } from "react-big-calendar";
import { format, parse, startOfWeek, getDay } from "date-fns";
import { enUS } from "date-fns/locale/en-US";

const localizer = dateFnsLocalizer({
  format,
  parse,
  startOfWeek: () => startOfWeek(new Date(), { locale: enUS }),
  getDay,
  locales: { "en-US": enUS },
});
```
